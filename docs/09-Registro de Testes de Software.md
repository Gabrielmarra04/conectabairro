## Relatório de testes de software

**- Caso de Teste CT01, CT02 e CT03.** <br/>
Com os testes realizados, percebemos que foi concluída com sucesso a realização do Requisito RF-01, visto o êxito ao coletar os dados essenciais e a facilidade de criar uma nova conta de usuário para ambos os Perfis selecionados. Retornando mensagens para o usuário com erros ou campos obrigatórios, facilitando o entendimento e a compreensão do usuário. Encontramos melhorias como adicionar um padrão de senha obrigatória, para melhor segurança do usuário, também na edição dessa senha, de modo que seja obrigatório informar a senha novamente, para confirmar que o usuário digitou a senha esperada.<br/>
O usuário consegue visualizar e realizar as alterações corretamente, sendo possivel enviar para o ADMIN a solicitação de troca de endereço ou então realizar a alteração de dados básicos como nome, Senha, E-mail e telefone. Retornando Feedback corretamente ao realizar a alterações de dados básicos ou alterações de dados que dependem da validação do ADMIN.<br/>
<br/>

**- Caso de Teste CT04 – Verificar se o usuário consegue realizar login.** <br/>
Está sendo possível realizar o Login no sistema corretamente inserindo os dados cadastrados anteriormente, caso seja inserido dados incorretos é exibido a mensagem de erro retornando o feedback ao usuário, sendo assim RF-02 foi concluído com sucesso com todos os seus requisitos atendidos.<br/>
<br/>

**- Caso de Teste CT05 – Verificar se o usuário consegue redefinir sua senha esquecida.** <br/>
Caso o usuário esqueça a sua senha, é possível trocar essa senha através do envio de um link para o e-mail cadastrado do usuário, sendo assim é possível alterar a senha e fazer o login novamente com a nova senha cadastrada. Sendo bem intuitivo e descrito para o usuário o passo a passo a ser realizado, podemos concluir que o RF-03 foi concluído com sucesso atendendo todos os requisitos propostos. <br/>
<br/>

**- Caso de Teste CT06, CT07, CT08 e CT09.** <br/>
CRIAÇÃO do post foi realizada com sucesso, sendo possível adicionar somente 1 anexo do tipo Foto e sinalizando corretamente a obrigatoriedade dos campos ao tentar publicar sem adiciona-los. Foram notadas possíveis melhorias como por exemplo adicionar mais imagens no Post, Adicionar vídeos curtos e também adicionar um campo de Valor para venda de produtos.<br/>
VISUALIZAÇÃO do Post foi realizada com sucesso, sendo assim possível ver os itens adicionados na criação, dados do Anunciador desse Post e possível também adicionar comentários e visualizar comentários adicionador por outros usuários no post e reagir com um Like ou Dislike. <br/>
EDIÇÃO do post foi concluída parcialmente, pois encontramos alguns pontos de ajustes como por exemplo ser possível editar os dados do Post sem ser necessário adicionar novamente o anexo. Mas tirando esse ajuste, é possível para o ADMIN, Ong e o criador do Post realizar edições como por exemplo o Status do Post.  <br/>
EXCLUSÃO segue uma regra parecida com a da edição, sendo possível somente para o ADMIN e o criador do Post realizar a exclusão do Post. Visto a necessidade de realizar a moderação ou exclusão de algum post que venha faltar com o respeito dentro da comunidade.<br/>
<br/>

**- Caso de Teste CT10 – Validar curtidas e comentários em publicações.** <br/>
Na visualização do Post, é possível adicionar ao Post um comentário e também uma curtida. Notamos um ajuste que seria exibir a contagem dessas curtidas no Feed e uma melhoria futura de ser possível adicionar uma curtida no comentário feito por outros usuários, aumentando a interação entre os usuários, podendo gerar mais engajamento.  <br/>
<br/>

**- Caso de Teste CT11 – Verificar se o usuário recebe notificações ao interagir.** <br/>
Foi criado o modal para exibição das notificações, porém devido o abandono do desenvolvimento por um colega do projeto, não foi possível finalizar o desenvolvimento com êxito do RF06.  <br/>
<br/>

**- Caso de Teste CT12 – Validar a busca e filtro de publicações.** <br/>
Foram adicionados os Filtros no Feed dos itens que foram considerados principais e importantes para o filtro, sendo eles o Título do Post ou a sua categoria. Encontramos uma futura melhoria como o Filtro de Status ou itens criados por mim, para auxiliar mais o usuário na busca por itens específicos. Podemos considerar o RF07 concluído com sucesso, visto que até o momento foram desenvolvidos todos os itens planejados para esse Requisito.  <br/>
<br/>

**- Caso de Teste CT13 – Verifique se ONGs/Prefeitura conseguem alterar o status.** <br/>
Nesse CT foram validados a segurança ao excluir ou Editar o Post, sendo validados corretamente sendo possível somente ao Usuário ou o Admin realizar a exclusão dos comentários e possível para o ADMIN, Ong e o criador do Post realizar edições como por exemplo o Status do Post. RF08, RF11 e RF16 concluídos com sucesso, pois atenderam a todos os requisitos propostos. <br/>
<br/>

**- Caso de Teste CT15 – Verificar se o administrador consegue excluir publicações.** <br/>
Essa permissão foi adicionada somente para o Usuário que criou o Post e para o ADMIN podendo excluir qualquer post. RF10 concluído com sucesso, pois atendeu as expectativas e está funcionando corretamente as permissões. <br/>
<br/>

**- Caso de Teste CT18 e CT19** <br/>
Foram adicionados travas na alteração do endereço do usuário. Para evitar que esse usuário mude constantemente de endereço, ao realizar a alteração do seu endereço em Meus Dados, é enviado uma solicitação para o ADMIN, para que ele possa validar essa solicitação, podendo recusar ou aprovar a alteração. Notamos uma melhoria a se fazer, sendo adicionar uma notificação para o usuário sobre a decisão do ADMIN, informando ao usuário qual foi a escolha do ADMIN, e adicionar uma informação mais detalhada para o usuário sobre essa necessidade de enviar uma solicitação de alteração de endereço. <br/>
<br/>

**- Caso de Teste CT22 – Validar alternância de tema claro/escuro.** <br/>
Por questão de sensibilidade, foi necessário ajustar algumas telas para um modo escuro, grande parte do sistema foi afetado positivamente, sendo ajustado corretamente para uma cor mais escuro. Foi encontrado uma melhoria em algumas telas devido a visualização de alguns textos que podem ter ficado de cores muito semelhantes, atrapalhando na usabilidade de alguns usuários.

### **CONCLUSÃO** <br/>
Conseguimos concluir grande parte do planejado no início do Projeto, com alguns pontos de melhorias que podem gerar grande valor ao sistema e também com grande RFs produzidos que causam grande impacto no sistema, trazendo uma boa usabilidade e fluidez do sistema.
